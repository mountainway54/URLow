# 資料庫操作

URLow 不會在 Worker 啟動或收到 request 時自動修改資料表。Migration 要在部署前，由開發者或 CI 明確執行。

## 部署前更新資料庫

1. 從 Neon 取得 direct、unpooled connection string。Hostname 不可包含 `-pooler`，網址也要有 `sslmode=require`。

2. 在目前的 PowerShell process 設定 `DATABASE_URL`。不要把正式連線字串寫進 Git 追蹤的檔案。

   ```powershell
   $env:DATABASE_URL="<NEON_DIRECT_URL>"
   ```

3. 檢查 Drizzle schema 是否還有未產生的 migration：

   ```powershell
   npm.cmd run db:generate
   git status --short drizzle server/database/schema.ts
   ```

   沒有變更時，`db:generate` 會顯示 `No schema changes, nothing to migrate`。

4. 先在乾淨的 Neon branch 演練：

   ```powershell
   npm.cmd run db:migrate
   npm.cmd run test -- --run tests/integration/short-url-schema.test.ts
   ```

5. 確認演練結果後，對正式 branch 執行 migration，再建置和部署：

   ```powershell
   npm.cmd run db:migrate
   npm.cmd run build
   npx.cmd wrangler deploy --dry-run
   npm.cmd run deploy
   ```

6. 部署後確認 `/api/health/database` 回傳 `200` 和 `{"status":"ok"}`。最後移除目前 process 的連線字串：

   ```powershell
   Remove-Item Env:DATABASE_URL
   ```

## 部署失敗時

Worker 程式和資料庫 schema 要分開處理，不要因為 Worker 部署失敗就立刻刪資料表。

1. 先用 Cloudflare Dashboard 或 Wrangler Versions，把 Worker 切回上一個正常版本。
2. 如果舊 Worker 不受新欄位或資料表影響，資料庫不需要 rollback。
3. 正式環境已經有資料時，優先再做一個 migration 修正問題。

只有確認沒有任何 Worker 使用該表、資料已備份，而且 migration 必須撤銷時，才在 Neon SQL Editor 或受控 CI 執行破壞性 SQL：

```sql
DROP TABLE IF EXISTS "short_urls";
```

這段 SQL 不可放進 Worker startup、request handler 或自動部署指令。執行前先建立 Neon branch 或 restore point。

`DATABASE_URL` 只給 Drizzle Kit 執行 migration。正式 Worker 透過 Cloudflare `HYPERDRIVE` binding 連接資料庫。
