# 除錯紀錄

這裡記下實際遇到的問題。每一段都先列症狀，再寫原因和修法，方便之後遇到相似情況時快速查找。

## Cloudflare Pages 的頁籤不能切換

早期版本部署到 Cloudflare Pages 後，畫面看得到，但「長網址縮址」與「短網址修改」無法切換。Console 顯示 Nuxt JavaScript chunk 回 `404`。

本機 `npm run generate` 正常，`.output/public/_nuxt` 也有新檔案。問題是瀏覽器還留著舊 HTML，裡面引用前一次部署的 chunk hash。用 `Ctrl + Shift + R` 強制重新整理或開無痕視窗後恢復。

當時的設定是：

```text
Build command: npm run generate
Build output directory: .output/public
```

這段只保留作為歷史紀錄。目前 URLow 是動態 Cloudflare Worker，不再用 Pages 靜態部署。若畫面出現但互動全部失效，仍可先檢查 Console 和 `/_nuxt/*.js`；Chunk 404 也可能是輸出目錄或部署不完整，不一定都是瀏覽器快取。

## PostgreSQL 無法在 Worker runtime 建置

最初遇到三個問題：

- Nitro `cloudflare` preset 輸出 Service Worker，無法使用 external `cloudflare:sockets`。
- `pg` 在 bundling 時嘗試解析選用的 `pg-native`。
- 設定的 compatibility date 比 Wrangler 內含的 workerd 新一天。

處理方式：

- 改用 Nitro `cloudflare_module`，輸出 ES Module Worker。
- 把 `pg-native` 指向 Worker shim，`cloudflare:sockets` 保留為 Rollup external。
- 將 `wrangler.jsonc` 的 compatibility date 設為 workerd 支援的 `2026-07-29`。

## 本機 Hyperdrive 找不到連線字串

Wrangler 4.115 啟動本機 Hyperdrive 前，就會檢查 process environment。只把連線字串放在稍後才載入的 `.dev.vars`，可能來不及。

曾出現：

```text
When developing locally, you should use a local Postgres connection string to emulate Hyperdrive functionality.
```

現在 `npm run cf:dev` 會先由 `scripts/cf-dev.mjs` 讀取 `.dev.vars`，驗證後放進 Wrangler process environment，再啟動 `wrangler dev`。

`.dev.vars` 只放：

```dotenv
CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_HYPERDRIVE=postgresql://USER:PASSWORD@DIRECT_HOST/DATABASE?sslmode=require
```

檔名必須是 `.dev.vars`，不是 `.dev.vars.txt` 或 `.dev.vars.example`。Neon host 要用 direct、unpooled endpoint，不能包含 `-pooler`。檔案已列入 `.gitignore`，不可提交。

Migration 使用的 `DATABASE_URL` 放在 `.env`，不會出現在 Worker bindings。Wrapper 也不會輸出 connection string。

啟動失敗後，Windows 偶爾會再顯示：

```text
Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c
```

這通常是 Wrangler 或 Node 清理程序時的次生錯誤。先往上找第一個 Hyperdrive 設定錯誤，不要從這行開始查。

## Compatibility date 比本機 runtime 新

Worker build 成功，但 `wrangler dev` 顯示：

```text
This Worker requires compatibility date "2026-07-30",
but the newest date supported by this server binary is "2026-07-29".
```

把 `wrangler.jsonc` 改為：

```json
{
  "compatibility_date": "2026-07-29"
}
```

這只改 Worker API 的 compatibility baseline，不會動到 KV、Hyperdrive 或資料庫 schema。

## PowerShell health check 跳出網頁剖析警告

Windows PowerShell 的 `Invoke-WebRequest` 可能要求確認指令碼執行風險。選 `N` 後看到 `WebCmdletIEParsingDeclined`，不代表 Worker 壞了。

可以改用：

```powershell
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:8787/api/health/database |
  Select-Object StatusCode, Content
```

或：

```powershell
curl.exe -i http://127.0.0.1:8787/api/health/database
```

成功時是 `200 {"status":"ok"}`；資料庫連不到時是 `503 {"status":"error","code":"DATABASE_UNAVAILABLE"}`。

## 首頁被短碼路由攔截

### 看到的情況

本機 Worker 的 API、health endpoint 和短網址都正常，只有首頁 `/` 回空白 `404`。`/_nuxt/*` 靜態檔案也能載入，所以不是整個 Worker 掛掉。

### 怎麼查到原因

一開始懷疑 `.output/public` 沒有 `index.html`，於是在 Wrangler 開啟 `assets.run_worker_first`，但首頁仍是 `404`。

比較路徑後發現：

```text
/x/y  → Nuxt HTML
/     → 空白 404
/abc  → 空白 404
```

原本的 `server/routes/[code].get.ts` 也會攔截根路徑。它收到空字串後設為 `404`，Nuxt renderer 沒機會處理首頁。只在 handler 裡 `return` 也沒用，因為 Nitro 已把這個 route 當成處理者。

### 修法

把動態 route 改成 middleware：

```text
server/routes/[code].get.ts
→ server/middleware/short-url-redirect.ts
```

Middleware 只處理 `GET`、`HEAD` 和單層路徑。根路徑、API 和多層網址直接略過，交回 Nuxt。

Wrangler 的靜態資源設定是：

```jsonc
"assets": {
  "binding": "ASSETS",
  "directory": ".output/public",
  "run_worker_first": [
    "/*",
    "!/_nuxt/*",
    "!/favicon.ico",
    "!/robots.txt"
  ]
}
```

修正後實測：

```text
GET /                    → 200 text/html
GET /api/health/database → 200 application/json
GET /As2fBrdp            → 302
GET /abc                 → 404
GET /favicon.ico         → 200
```

重複啟動 Wrangler 時也遇過殘留的 workerd／Node 鎖住 `.output/public`，造成 `EBUSY`。停止這個專案舊的 `cf:dev` 程序樹後即可重建，不需要刪資料庫。

## `/api-docs` 有內容卻回 404

OpenAPI JSON 正常，但 Swagger 頁面回 `404 text/html`。奇怪的是，response body 已經有 `/api-docs` 的 Nuxt HTML。

原本 Swagger 頁面靠 `app/app.vue` 讀取 `useRoute()` 後切換元件，這不會建立正式的 Nuxt Page。先改為：

```text
app/pages/index.vue       → 首頁
app/pages/api-docs.vue    → Swagger UI
app/app.vue               → NuxtPage
```

重新建置後還是 `404`。接著發現 `/api-docs` 是單層路徑，而且符合短碼允許的字元。Redirect middleware 先把 `api-docs` 當短碼查詢，查不到後把 status 設成 `404`；Nuxt 雖然接著渲染頁面，狀態碼沒有被改回來。

修法是在 middleware 保留應交給 Nuxt 的路徑：

```ts
const RESERVED_APP_PATHS = new Set(['/api-docs'])
```

`/api-docs` 和 `/api-docs/` 都會略過短碼查詢。回歸測試也確認這兩個路徑不會讀 KV 或 PostgreSQL。

## `/api-docs` 回 200，但畫面空白

修正狀態碼後，頁面回 `200`，Console 也沒有 JavaScript 錯誤，畫面卻沒有 Swagger UI。

當時元件檔名是：

```text
app/components/SwaggerApiDocs.client.vue
```

整個頁面只有這個 client-only 元件，所以 Server HTML 只有 placeholder。本機 Worker 沒有成功把 placeholder 換成實際元件，`onMounted` 也沒有執行。

我把它改成一般 Vue 元件 `SwaggerApiDocs.vue`。SSR 先輸出 Swagger 的掛載節點，瀏覽器 mounted 後再動態 import `swagger-ui-dist/swagger-ui-es-bundle.js` 並載入 `/api/openapi.json`。

驗證時同時檢查三件事：

```text
GET /api-docs         → 200 text/html
GET /api/openapi.json → 200 application/json
瀏覽器畫面             → 顯示 Swagger UI
```

這個問題只看 HTTP 200 會漏掉，所以最後一定要用瀏覽器確認實際畫面。
